# 「字修」角色 Mod — v1 规格

## Problem Statement

我想给《杀戮尖塔 1》做一个以汉字拆解为核心的原创角色「字修」。手上已经有一份 85 字的拆解分级表，但表本身不自洽：

- 撞车：`本`/`末`/`未` 同为 {木, 一}，`回`/`吕` 同为 {口, 口}，`呆`/`杏`/`困`/`束` 同为 {口, 木}。
- 拆不出：`里` 需要 `田`、`永` 是独体、`且` 只能勉强拆。
- 生僻：`汕`/`汨`/`沓`/`圭`/`哇` 既想留又想扔。

这份表不能直接当规则用。我需要一套能落地的机制、一份可以直接照着填的牌池，以及一条能先跑起来的实现路径——而不是更多零散的会议结论。

## Solution

把「拆」和「合」做成**免费、不限次数**的手牌基础动作：两张部件牌拼成一个字，任意成品牌右键拆回部件。撞车不靠砍字、也不靠位序解决，而是由**选字面板**让玩家在成型前挑一个结果。

配一张**手写的配方表**作为唯一真相，85 字全部保留：

- 10 个部件（人、口、木、月、土、一、水、火、山、日）既是 0 费可打出的卡牌，也是拼合材料。
- 3 条主脉：**焚**（灼烧不递减 + 引爆）、**润**（剩余格挡换抽牌 + 拆解续航）、**照**（消耗型曝光 + 折射倍增）。
- v1 交付 = 一个 BaseMod 角色：70 血、3 能量、10 张起始牌组、45 张成品牌、7 遗物、3 药水、2 事件。

## User Stories

### 拼合

1. 作为玩家，我想在选中两张部件牌时看到它们能拼出的所有字，这样我不需要背配方表。
2. 作为玩家，我想在 `口+木` 这种多结果组合里自己挑一个字成型，这样同一个组合能打出不同流派。
3. 作为玩家，我想让拼合不消耗能量、不限次数，这样拼字是我随时能做的动作而不是资源。
4. 作为玩家，我想让拼不出有用字的组合不高亮、不可选，这样我不会把回合浪费在废字上。
5. 作为玩家，我想让拼合出的成品牌立刻进手牌，这样拼字的收益当回合就能兑现。
6. 作为玩家，我想在选字面板里看到每个结果的花费和类型，这样我知道选哪个更值。
7. 作为玩家，我想把成品牌当材料继续拼（`林+木 → 森`），这样大字的路线不止一条。
8. 作为玩家，我想看到 `口+口` 能出 `回` 或 `吕`，这样「同一组部件写出不同字」是这个角色的常态而不是 bug。

### 拆解

9. 作为玩家，我想右键任意成品牌把它拆回部件，这样我总能把不想要的字换成材料。
10. 作为玩家，我想让拆解免费且不限次数，这样我敢在关键回合把整手牌重写。
11. 作为玩家，我想让被拆掉的牌进消耗堆，这样拆解有代价、不会变成无限资源。
12. 作为玩家，我想让本回合合出来的牌当回合不能拆（墨迹未干），这样我不会掉进无限拆合的循环。
13. 作为玩家，我想让 `品`/`淼`/`合` 虽然拼不出来但拆得开，这样抽到它们仍然有用。
14. 作为玩家，我想让 `永` 全池唯一不可拆，这样独体字有独体字的规矩。
15. 作为玩家，我想让 `圭` 这种中间字能拼出来、不能打出，这样 `佳`/`桂`/`洼`/`垚` 有可达路径。
16. 作为玩家，我想在拆三部件字时手牌溢出自动进弃牌堆，这样 UI 不会卡住。

### 三条主脉

17. 作为焚玩家，我想让灼烧回合结束掉血且不递减，这样长战里群烧真的能赢。
18. 作为焚玩家，我想让引爆类牌立刻结算并清除灼烧，这样铺完有一发终结。
19. 作为焚玩家，我想有「自伤换输出」的备用线，这样抽不到灼烧组件时也能打。
20. 作为润玩家，我想让剩余格挡换抽牌，这样过度格挡是引擎而不是浪费。
21. 作为润玩家，我想靠拆解把大牌换回部件续航，这样润有第二套资源。
22. 作为润玩家，我想有治疗与净化，这样我能扛住持续伤害的敌人。
23. 作为照玩家，我想让曝光是「每受伤一次减 1」的消耗型增伤，这样叠层和爆发有节奏。
24. 作为照玩家，我想让 `晶` 把曝光翻倍，这样铺满之后有一发倍增。
25. 作为照玩家，我想有抽牌引擎，这样我能在一回合里连出多个成品牌。
26. 作为玩家，我想三条脉各有 6 普通 / 5 罕见 / 4 稀有的曲线，这样每局都能摸到完整流派。

### 角色与内容

27. 作为玩家，我想开局手牌里同时有笔画基础牌、部件牌，这样我第一回合就能理解角色结构。
28. 作为玩家，我想让部件牌 0 费且有效果（2 伤 / 2 甲 / 抽 1 之类），这样它们不是死牌。
29. 作为玩家，我想让起始遗物立刻教我合字，这样第一场战斗就能摸到核心机制。
30. 作为玩家，我想让 7 个遗物分别挂在三条脉和拆合系统上，这样选遗物等于选修流派。
31. 作为玩家，我想让药水能直接给材料、上灼烧、复制成品牌，这样药水不只是数值。
32. 作为玩家，我想让事件围绕「错字」「残卷」这类主题，这样文字世界的氛围不断。
33. 作为玩家，我想让灼烧 / 曝光 / 墨迹未干都有清晰的关键词提示，这样我不用查百科。

### 设计师与实现者

34. 作为设计师，我想让配方表是唯一真相，这样我加一个字只改数据、不改逻辑。
35. 作为设计师，我想让撞车由选字面板消化，这样我不用为了可拼性砍掉 `吕`/`束`/`未`。
36. 作为设计师，我想让 85 字全部保留，这样字表口径不变。
37. 作为设计师，我想把字分成「成品牌 / 字胚 / 废字 / 无配方牌」四类，这样每个字都有明确归属。
38. 作为实现者，我想有一个纯函数的字学核心，这样我能在没有游戏引擎的情况下测规则。
39. 作为实现者，我想让配方键是「展开后的部件多重集」，这样 `林+木` 与 `木+木+木` 走同一条查表逻辑。
40. 作为实现者，我想让拼合和拆解共用同一个手牌面板，这样 UI 只有一套交互。
41. 作为实现者，我想让「墨迹未干」判定只依赖「本回合新生成牌的 id 集合」，这样它不依赖牌面或玩家状态。
42. 作为实现者，我想让卡牌效果与字学核心解耦，这样加牌不改核心。
43. 作为实现者，我想先做最小可玩原型（3 张部件 + 1 张成品牌 + 一次合、一次拆），这样最大风险先被验证。

## Implementation Decisions

### 平台与依赖

- 目标为《杀戮尖塔 1》，依赖 ModTheSpire + BaseMod + StSLib。
- 只做中文 v1，但所有文案走 key，留英文接口。
- 不使用角色专属第四条资源条：角色唯一的「资源」就是手牌里的部件。

### 字学核心（唯一测试缝）

核心是一个**纯函数模块**，不认识任何 StS 类型。所有规则判定都在这里，游戏层只做适配。

```java
enum Component { REN, KOU, MU, YUE, TU, YI, SHUI, HUO, SHAN, RI }

record RecipeKey(List<Component> expandedParts) {}   // 已排序，顺序无语义

record WordSpec(
    String glyph,            // 呆
    List<Component> parts,   // 展开后的部件
    WordRole role            // PLAYABLE / SEED / JUNK / NO_RECIPE
) {}

Map<RecipeKey, List<WordSpec>> RECIPES;

List<WordSpec> optionsFor(List<Component> expandedParts);  // 供拼合
List<Component> partsOf(String glyph);                    // 供拆解
```

- **配方键是展开后的部件多重集**。`林` 展开为 {木, 木}，所以 `林+木` 与 `木+木+木` 命中同一个键。
- 一个键可以对应多个 `WordSpec`，这就是选字面板的数据来源。
- 异体归并：亻→人、氵→水、灬→火、士→土、囗→口。卡面美术保留原字形，机制层只认归并后的部件。
- 不做位序：先后选择不改变结果。

### 拼合

- 免费、不限次数。输入为 2 张手牌（部件牌或成品牌均可），各自展开为部件多重集后相加。
- 查表后**只返回有用结果**（`PLAYABLE` 或 `SEED`）。`JUNK` 与无结果组合不返回，UI 不高亮、不可选。
- 只有一个结果时直接成型；多个结果时弹选字面板。
- 成型后的成品牌进入手牌，标记为本回合新生成（见墨迹未干）。

### 拆解

- 免费、不限次数。对任意手牌里的成品牌右键触发。
- 按 `partsOf(glyph)` 还原全部部件，部件进手牌；原牌进**消耗堆**。
- 拆解不受拼合的「2 张」限制：`品` 拆回 3 张口。
- `NO_RECIPE` 且独体的字（`永`）不可拆。

### 墨迹未干

- 维护「本回合由拼合生成的牌」集合；集合内的牌本回合不可拆解。
- 这是防止 `拆 呆 → 合 杏 → 拆 杏 → 合 呆` 无限循环的唯一手段，必须有。

### 手牌 UI

- 拼合：选中两张手牌后出现「合」按钮；点击后若多结果则弹选字面板，否则直接成型。
- 拆解：右键成品牌，弹同构的部件预览面板，确认后执行。
- 面板复用同一套组件，避免两套交互记忆。

### 三条主脉

| 脉 | 核心 | 关键词 |
|---|---|---|
| 焚 | 灼烧叠层 → 引爆 | 灼烧不递减；`灭` 对灼烧目标伤害翻倍并清除 |
| 润 | 剩余格挡 → 抽牌 | 回合结束每 3 点未用完的格挡抽 1（上限 2）；治疗与净化 |
| 照 | 曝光叠层 → 一回合兑现 | 曝光每受伤一次减 1；`晶` 使曝光层数翻倍 |

「拆」是跨脉的投资线：`森`（拆解得甲）、`炅`（拆解叠曝光）、`淡`（拆解净化）、`崩`（按拆解次数加伤）。

### 角色本体

- 70 最大生命，3 能量，初始 0 金币。
- 基础牌：`击`（1 费 6 伤）、`守`（1 费 5 甲）。不进奖励池、不计入 85 字口径。
- 起始牌组 10 张：4× 击、3× 守、3× 部件（火 / 木 / 口）。
- 起始遗物「秃笔」：战斗开始时将 1 张随机部件牌加入手牌。

### 数据待补

- 85 字的完整配方表（glyph、展开部件、role）。
- 45 张牌的最终数值（现有 `docs/cards-v1.md` 为初稿）。
- 7 遗物、3 药水、2 事件的最终文案。

## Testing Decisions

- **唯一的测试缝是字学核心**。它是纯函数，不引用任何 StS 类型，用 JUnit 直接测。
- 好测试的标准：只验证外部行为——给一组部件，断言能出哪些字；给一个字，断言拆回哪些部件；给一个「墨迹未干」集合，断言能否拆解。不测内部数据结构。
- 必测用例：
  - `{口, 木}` → 呆 / 杏 / 困 / 束（四选一）。
  - `{木, 一}` → 本 / 末 / 未（三选一）。
  - `{口, 口}` → 回 / 吕；`{日, 木}` → 杲 / 杳；`{口, 土}` → 吐 / 吉。
  - `{水, 水, 水}` → 无结果（`淼` 不可拼）。
  - `{口, 口, 口}` → 品（`回+口` 可达）。
  - `{水, 山}` → 汕 为 `JUNK`，不返回。
  - `{土, 土}` → 圭 为 `SEED`，可返回但不可打出。
  - `partsOf("品")` → 三口；`partsOf("永")` → 空。
  - 本回合新生成的牌 → 不可拆。
- 卡牌效果、遗物触发、UI 流程不写单元测试，走 BaseMod 内的手动试玩清单。
- 没有任何现成代码可作先例，这是首个测试缝。

## Out of Scope

- 《杀戮尖塔 2》。
- 美术、音效、动画。
- 升天难度调优与心脏/终局平衡。
- 85 字里未进 v1 的 40 张牌。
- 英文与其他语言的正式翻译（只留 key）。
- 存档兼容与旧版本迁移。
- 遗物 / 药水 / 事件的最终数值与文案定稿。

## Further Notes

- **最大风险是手牌 UI**，不是规则。所有规则都可以在纯核心里边写边测；手牌选中、右键、动态造牌、面板弹出这四件事在 StS1 上都有先例，但没有一件是「开箱即用」。
- 因此第一个里程碑应该是：3 张部件牌 + 1 张成品牌 + 一次拼合 + 一次拆解，能在真实战斗里跑完一回合。牌池、遗物、文案全部压在这个原型之后。
- 相关 ADR：`docs/adr/0001`（平台）、`0002`（手牌拼字为核心机制）、`0003`（配方表为唯一真相）。
- 本工作区没有配置 issue tracker，本规格暂存为文件；若要发布到 tracker，需先运行 `/setup-matt-pocock-skills`。
