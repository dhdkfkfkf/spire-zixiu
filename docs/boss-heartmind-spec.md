# 终局 Boss 设计与 Zcode 实施任务书：心魔·旧我

> 文档性质：设计参考 + 源码现状审计 + 分阶段实施任务。  
> 本 PR **只提交文档，不包含 Java/资源/配置改动，不代表 Boss 已实现**。  
> 面向实施工具：**Zcode**。Zcode 应先审查本任务书和当前代码，再独立验证技术路径；不得把设计文稿当成未经审查的硬编码方案。

## 0. 给审查者 / Zcode 的执行摘要

目标是在字修角色砚秋的终局流程中，提供一个可选专属 Boss「心魔·旧我」，与原版心脏二选一。原版心脏必须完整保留。Boss 设计为两个阶段，以数值压力验证成熟卡组，不做复杂机制试炼。整局记录玩家的战斗习惯，生成 Boss 的「旧稿」战斗个性；第一阶段有限临摹，第二阶段逐渐转为心魔自己的「伪字」招式。

**最重要的体验约束：觉醒演出必须快。** 心魔生命值首次低于最大生命值 50% 时，场景、立绘和火焰特效作为一个整体快速切换；不串联冗长动画、不恢复生命、不生成第二条血条、不重置战斗。演出期间暂停战斗推进与玩家输入，结束后立即恢复正确的第二阶段意图。

本 PR 的用途是让用户和 Zcode 共同审查、拆分任务和实施。不要直接照文档一次性大改终局流程。

## 1. 设计目标与边界

### 1.1 角色与剧情主题

心魔不是邪恶版砚秋，也不是单纯的怪物。它是砚秋对家道中落、身份失去和无法挽回的过去的执念具象化。

- 心魔坚信：只要找到正确的字，就能改写命运、挽回过去的一切。
- 它相信文字足以恢复旧日家世、身份、体面和受人尊敬的生活。
- 砚秋逐渐理解：文字能帮助人认识世界，却不能让所有已经发生的事情重新发生。
- 心魔并不认为自己在伤害砚秋；它认为自己是在帮助砚秋找回失去的一切。
- 最终冲突不是善恶对决，而是「执意改写过去」与「接受过去、继续向前」的冲突。

### 1.2 选角与兼容边界

砚秋选角界面增加终局 Boss 选择：
- 默认：原版心脏。
- 可选：字修专属 Boss「心魔·旧我」。
- 仅对砚秋生效；其他角色、原版流程和其他 Mod 不受影响。
- 用户必须能清楚看出当前选择；选择应在开局时被固定，避免局中配置变化影响已生成的终局流程。
- 原版心脏路径必须保持原样，不应被全局替换或通过不受限的全局 Hook 改写。

UI 可参考现有 `CharSelectRulesButton` 的选角界面绘制和输入处理，但 Boss 选择必须拥有独立配置状态、独立命中区域和清晰的默认值，不得复用或污染拆合规则设置。

### 1.3 难度哲学

目标难度：略高于原版心脏，但不是极限构筑专属挑战。

- 以数值试炼为主：输出、防御、续航和持续作战能力。
- 不强迫特定字、特定流派或某种卡牌循环。
- 不因玩家选了强牌、重复打出某牌或采用成熟构筑而暗中抬高基础数值。
- 不做必须破解的复杂规则，不用禁牌、反伤循环或不可读的隐藏成长来惩罚玩家。
- 不靠无限堆血制造难度；攻击压力和防御窗口要可读、可应对。
- 第二阶段进攻压力明显提升，但要留给玩家合理的结束战斗窗口。
- 「旧稿」只塑造 Boss 的行为个性，不决定其总体难度。

## 2. Boss 战斗设计

### 2.1 两阶段结构

只采用两个阶段，不增加第三阶段。

#### 第一阶段：「旧稿」

主题：体面、克制、执着。

- 心魔保持昔日贵公子的仪态；衣着整洁，举止从容，保留砚秋的面部和轮廓辨识度。
- 场景：完整、安静、有秩序的旧书房，书桌、笔墨、书籍和纸张构成主体。
- 战斗风格：临摹与有限改写。
- 依据本局「旧稿」数据选择少量代表性招式，呈现玩家真实的战斗习惯。
- 不直接复制玩家卡牌的全部效果；临摹招式必须是独立平衡过的 Boss 行动。
- 台词方向：「你看，你明明还记得。」「既然如此，为何非要向前走？」

#### 第二阶段：「妄书」

主题：失控、偏执、崩溃。

- 心魔无法接受过去不可挽回，开始不计代价地创造答案。
- 场景：同一书房被火焰、墨迹和扭曲文字吞没；与第一阶段形成鲜明反差。
- 立绘保留砚秋辨识度，但衣袍、发丝、表情和姿态发生变化，呈现失控状态。
- 战斗风格：妄造与伪字。伪字是心魔制造的异常文字，不属于玩家正常的合字体系，也不要求玩家掌握或破解新规则。
- 伪字只作为 Boss 行动的主题包装和技能表达，例如：扭曲防御字（高防但有明确回合窗口）、失控攻击字（高伤且可伴随自损）、残缺恢复字（有限、不稳定的恢复表现）。
- 第二阶段更激进、更偏进攻；数值压力提升，但不能变成不透明的强制解题。
- 台词方向：「不对……一定还有办法。」「我只差最后一个字……」

### 2.2 觉醒阈值与快速演出（硬性要求）

触发条件：Boss 当前生命值**首次低于最大生命值的 50%**。只触发一次。

战斗规则：
- 沿用同一条生命值，不生成第二条血条。
- 不恢复生命、不重置战斗、不清空玩家状态、不额外结算伤害。
- 阈值跨越必须稳健：一次伤害直接从 51% 打到 20% 也只触发一次。
- 触发后锁定演出状态，防止重复触发、玩家输入、敌我回合推进、意图错位或额外伤害。
- 演出结束时重新确认并展示第二阶段的正确意图，恢复战斗。

演出顺序应是**同步快速切换，而不是多个长动画串行播放**：
1. 旧书房、旧立绘开始燃烧/扭曲；
2. 场景切换、觉醒立绘切换、火焰爆发基本同步发生；
3. 极短停顿后结束演出，立即回到战斗。

时长建议：整体约 0.6–1.0 秒作为初始目标，必须在实际游戏中测量后再确定；这不是未经验证的引擎保证值。可以使用短促闪白/墨火爆发和静态图切换，不要为了这个 Boss 引入复杂 Spine 动画系统，除非 Zcode 证明现有资源体系无法满足且用户同意。

**验收底线**：
- 演出不能明显拖慢回合节奏；不能出现黑屏等待、长时间镜头停留或多个全屏动画依次播放。
- 场景与立绘切换必须同步或近乎同步。
- 玩家在演出期间不能操作；敌方也不能趁演出推进行动或追加伤害。
- 演出结束后玩家状态、Boss 当前生命值、回合归属和意图均正确。
- 觉醒只发生一次；Boss 被击杀、玩家死亡或战斗结束时不得再启动觉醒流程。
- 低帧率、暂停/恢复、快速连击和跨阈值伤害下都不能卡死。

## 3. 「旧稿」：整局学习与战斗内补充学习

### 3.1 核心原则

整局爬塔期间记录玩家战斗习惯，Boss 战开始时生成稳定的「旧稿」。旧稿让心魔显得认识砚秋、记得玩家一路如何战斗，而不是读取玩家完整牌组并照搬。

记录候选维度：
- 合字频率、常用组合倾向；
- 拆字频率；
- 连书行为；
- 墨迹体系行为；
- 攻击、防御、资源运营等宏观倾向；
- 少量代表性成品牌及其使用频率。

具体采样应有限、有上限、低开销。避免保存完整战斗日志、无限增长的数据结构或把每次出牌都转成复杂快照。

### 3.2 行为表现

- 第一阶段按旧稿挑选少量临摹/改写招式。
- 第二阶段逐渐不再复制玩家，而是创造心魔自己的伪字招式；旧稿只作为叙事素材或少量招式选择依据。
- 战斗内可观察玩家是否重复某种战术，并有限调整后续招式选择。
- 不因重复使用某张牌直接反伤、禁用或无限成长。
- 不强制玩家改变流派，不隐藏不可读的难度惩罚。
- 学习结果通过意图、动作、台词或明确视觉反馈表达。

台词方向：
- 入场：「我替你把一路走来的字，都收好了。」
- 第一阶段：「这些字，我都认得。」
- 战斗中：「你又变了……你究竟想写出什么？」
- 第二阶段：「不对……这不是我记得的你。」

### 3.3 数据生命周期与默认行为

Zcode 需设计独立的 Run-scoped tracker / snapshot，不要把「旧稿」直接塞进现有的回合/战斗状态容器。

至少定义：
- 新开局初始化；
- 只在砚秋使用时采样；
- 每场战斗、每次行动的采样边界；
- 计数上限和采样偏差控制；
- 进入 Boss 战时生成不可变快照；
- 无记录、数据异常或某维度缺失时的默认旧稿；
- Boss 战内补充学习的局部状态；
- 战斗结束/Run 结束时清理；
- 不得跨局残留，也不得影响其他角色或原版心脏。

默认方案必须能独立成立：没有有效旧稿时，心魔使用固定、平衡、完整的基础招式池，Boss 不得因此变弱到失去战斗内容或强到不可战胜。

## 4. 战败、通关与现有结局衔接

心魔战败不应像普通怪物一样爆炸消失。

建议结尾：
1. 心魔逐渐变回砚秋的模样。
2. 最后问：「那么……你真的不再回头了吗？」
3. 砚秋不回答，转身走向书房的门。
4. 接入砚秋现有四张通关分镜：空荡书房；砚秋在书房写字；砚秋起身看向窗外、书页被风吹起；砚秋推门走向门外的光，光里隐约有古建筑。

现有代码的 `ZixiuCharacter` 已通过 `getCutsceneBg()` 和 `getCutscenePanels()` 提供结尾背景及三张 panel 图片（背景 + 三张 panel 合计四幅画面）。Zcode 应先确认游戏实际播放时序，再决定如何接入 Boss 专属结尾；不要误把背景图与 panel 数量计算成四张 panel。

四张分镜之后增加全黑文字页：
- 纯黑背景，无卷轴、纹理、边框、插图。
- 居中显示《归去来兮辞》三组两句，共六行；六行横排，组间距更大。
- 文本：
  - 既自以心为形役，奚惆怅而独悲？
  - 悟已往之不谏，知来者之可追。
  - 实迷途其未远，觉今是而昨非。
- 雅致宋体优先，其次易读楷体；温润米白/淡暖灰。
- 不加标题、作者署名或额外格言。
- 整段淡入约 1.5–2 秒，不逐字显示；不自动消失，等待玩家点击，再进入正式胜利结算。
- 只作用于砚秋选择心魔 Boss 的通关流程；原版心脏和其他角色结尾保持不变。

2. 心脏 encounter 的注册、实例化和进入战斗调用链；区分原版怪物生成与房间/地图推进。
3. 战斗胜利回调、房间清理、结局 Cutscene、胜利统计界面的调用顺序。

5. 适合局部接入的 Hook：优先针对砚秋且只在该 Run 生效；避免全局替换心脏类或影响所有角色。
6. 战斗内切换场景/立绘/特效的渲染与更新生命周期；怎样短暂冻结输入和战斗推进。
7. 现有资源加载、释放和缓存方式；避免每帧加载纹理或产生资源泄漏。

每一项需附实际方法名、类名、调用顺序和证据（反编译源码位置/签名/运行日志）。若某项只能通过实验确认，应明确标为待验证，不要把推测写成事实。

## 6. 建议的实施拆分（由 Zcode 审查后执行）

### Phase 0 — 只读调查与技术方案

- 阅读本文件、`GLOSSARY.md`、`docs/adr/`、`docs/handoff-2026-11-24.md` 和现有实现。
- 完成第 5.3 节调用链调查。
- 输出最小侵入的实现方案：候选 Hook、数据生命周期、战斗入口、胜利结算出口、资源组织、兼容策略。
- 明确哪些部分能用现有 BaseMod subscriber，哪些必须使用 ModTheSpire patch。
- 在用户审查方案前，不开始改动终局主流程。

### Phase 1 — Boss 选择与原版兼容

- 增加独立 Boss 选择状态，默认原版心脏。
- 只在砚秋选角界面显示；UI 清晰显示当前选择。
- 开局时将选择固定到当前 Run；新开局重置为默认值。
- 验证原版心脏路径完全不变；其他角色不显示也不读取此选择。
- 不在此阶段同时实现自定义 Boss 和剧情演出。

### Phase 2 — 心魔基础战斗

- 新增独立 Monster/Encounter/行动定义，按项目当前 API 版本实现。
- 先完成两阶段之外的基础战斗循环：生命值、意图、攻击/防御数值、死亡处理。
- 初期可以用固定招式池，保证无旧稿数据也能正常打完整场战斗。
- 验证敌方意图、伤害、格挡、力量/易伤等常规机制和原版规则一致。
- 数值需要通过实战调试；不要把文档中的方向描述当成已经平衡的具体数值。

### Phase 3 — 50% 觉醒与快速场景切换

- 在伤害结算后以可靠时点检测首次低于 50%。
- 觉醒状态机必须幂等，避免多次触发。
- 同步切换场景、立绘、火焰特效。
- 用短时状态锁阻止玩家输入与敌我行动推进；演出结束恢复正确战斗状态。
- 做跨阈值伤害、连击、低帧率、暂停/恢复、击杀时点测试。
- **快速演出是验收阻断项**，不可为了完成特效而牺牲节奏。

### Phase 4 — 旧稿记录与 Boss 个性化

- 先实现 Run tracker 和稳定 snapshot，补齐无数据默认值。
- 逐步加入第一阶段少量临摹招式。
- 第二阶段再加入伪字行动与战斗内有限学习。
- 所有学习效果都应有明确上限、可读提示和可预测的战斗强度。
- 不允许 tracker 污染其他角色、原版心脏或下一局。

### Phase 5 — 战败结尾与结算衔接

- 心魔专属战败演出。
- 复用/扩展现有四幅通关分镜。
- 增加全黑诗句页和点击继续。
- 验证最终仍进入正确的原版胜利结算，不重复触发、不跳过、不锁死。
- 仅当玩家选择心魔 Boss 且砚秋胜利时启用。

### Phase 6 — 回归与交付

- 构建：沿用仓库 Java 8 构建脚本/PowerShell 对应脚本。
- 运行测试：`scripts/test.sh` 及项目现有测试。
- 实际游戏测试：普通难度、进阶难度、不同卡组类型、无旧稿数据、极端伤害跨阈值、原版心脏选择、其他角色通关。
- 提交实现 PR 前附构建日志、游戏日志、关键流程录屏/截图或人工测试清单。
- 不要把「编译通过」等同于「终局流程正确」。

## 7. 验收清单

- [ ] 砚秋选角界面能选择原版心脏或心魔·旧我，默认原版心脏。
- [ ] 新 Run 的选择状态正确初始化，不继承上一局意外状态。

- [ ] 原版心脏选择的地图、战斗、结局和胜利结算完整回归通过。

### Boss 战斗
- [ ] 心魔拥有清晰的两阶段行动循环。
- [ ] 第一阶段临摹玩家风格，但不直接复制卡牌效果。
- [ ] 第二阶段伪字仅作为 Boss 行动，不污染玩家字库。
- [ ] 难度略高于心脏，主要来自可读的数值压力，不要求特定流派。
- [ ] 无旧稿、数据缺失或异常时仍可完成战斗。

### 觉醒
- [ ] 首次低于 50% 时只触发一次；同一条血条，不回血、不重置。
- [ ] 场景、立绘、火焰同步快速切换。
- [ ] 演出整体短促，初始目标约 0.6–1.0 秒，实际以游戏测量为准。
- [ ] 演出中玩家不能操作，敌人不能行动，不产生额外伤害。
- [ ] 演出结束后战斗状态和意图正确；击杀时不触发觉醒。
- [ ] 低帧率/暂停恢复/大额伤害/连击不会导致卡死或重复触发。

### 旧稿
- [ ] 数据只在砚秋当前 Run 记录；有上限、可重置。
- [ ] Boss 战开始时形成稳定快照。
- [ ] 第一阶段少量临摹，第二阶段以伪字为主。
- [ ] 学习行为不会无上限增加难度或强迫玩家换流派。
- [ ] 其他角色和原版心脏完全不受影响。

### 结尾
- [ ] 心魔战败演出与砚秋剧情主题一致。
- [ ] 四幅画面衔接顺序正确。
- [ ] 黑底诗句页符合排版、淡入和点击继续要求。
- [ ] 最终进入原版胜利结算；其他角色/原版心脏流程不变。
